## 二、重点错题与含糊题回看

### 1. 把 `FF` 误认为 `1515`

- 错误位置：第二组第 3 题。
- 正确理解：十六进制是进位制，不能把每一位的十进制值直接拼起来。
- 例子：`0xFF = 15*16 + 15 = 255`。
- 工程意义：芯片手册、寄存器、波形窗口常用十六进制显示，必须熟悉位权，否则很容易误读寄存器值。

### 2. 无符号和补码的解释方式混淆

- 错误位置：第一组第 2 题、第二组第 4 题、第六组第 9 题。
- 正确理解：同一串 bit 可以有不同解释。
- 例子：`1111_1111` 作为 8 位无符号是 `255`，作为 8 位补码是 `-1`。
- 工程意义：信号本身只是 bit，真正含义来自设计约定、接口说明、寄存器字段定义。

### 3. 对补码范围公式不稳

- 错误位置：第一组第 3 题、第五组第 1 题。
- 正确公式：
  - n 位无符号：`0 ~ 2^n - 1`
  - n 位补码：`-2^(n-1) ~ 2^(n-1)-1`
- 例子：4 位补码是 `-8~+7`；8 位补码是 `-128~+127`。
- 工程意义：定点数据、偏移值、误差值、传感器读数等有符号字段都受位宽范围限制。

### 4. “数学真实结果”和“固定位宽保存结果”混淆

- 错误位置：第四组第 5 题、第五组第 3/4 题、第六组第 9/11 题。
- 正确理解：加法器可以算出进位，但如果寄存器只有 n 位，只能保存低 n 位。
- 例子：`1111 + 0001 = 1_0000`，4 位结果只保存 `0000`，最高的 `1` 是 carry out。
- 工程意义：计数器回绕、长度字段溢出、累加器截断都和固定位宽有关。

### 5. carry out 不能直接当作符号扩展后的最高位

- 错误位置：第五组第 4 题。
- 正确理解：如果要把补码从 4 位扩展到 5 位或更多位，应先做符号扩展，而不是把加法产生的 carry out 拼到结果前面。
- 例子：4 位 `1111` 表示 `-1`，扩展成 5 位应是 `11111`，不是只在结果前随便拼一个进位。
- 工程意义：不同位宽模块连接时，必须明确是零扩展还是符号扩展。

### 6. 显示进制和编码规则混在一起

- 错误位置：第六组第 15 题。
- 正确理解：二进制、十进制、十六进制主要是显示/书写方式；无符号、补码、BCD 是编码解释规则。
- 例子：`1111_1110`、`0xFE`、`254` 可以描述同一个 8 位无符号值；但 `0xFE` 作为 8 位补码又是 `-2`。
- 工程意义：波形工具里改 radix 只是改变显示方式，不会改变底层 bit。

## 三、目前薄弱掌握点

1. **十六进制位权还需要更熟**  
   重点是不要把 `FF` 理解成 `1515`。十六进制每一位都有 `16^k` 的权重。

2. **位宽意识需要继续强化**  
   同样是 `1111`，4 位就是 4 位；如果变成 8 位，必须明确是零扩展还是符号扩展。

3. **补码溢出的判断还不够自动化**  
   目前能理解现象，但还需要继续练“数学结果、保存下来的 bit、补码解释值”三者分开看。

4. **carry out 与补码符号扩展容易混淆**  
   carry out 是加法器产生的进位；符号扩展是改变位宽时复制最高位。两者不是同一件事。

5. **显示方式和编码方式还需要区分**  
   二进制、十六进制、十进制是写法；无符号、补码、BCD 是解释规则。

6. **工程语境下的字段含义还要建立直觉**  
   计数器、地址、长度一般按无符号理解；偏移、误差、温度差等可能按有符号补码理解。

## 四、必要基础知识整理

### 1. bit 与位宽

- 1 bit 只有两种状态：`0` 或 `1`。
- n bit 一共有 `2^n` 种不同状态。
- 位宽决定能表示多少种状态，也决定加法、计数、截断时最多能保存多少 bit。

例子：

```text
4 bit：共有 2^4 = 16 种状态
8 bit：共有 2^8 = 256 种状态
```

工程理解：数字电路里的寄存器、总线、计数器、数据字段都有固定宽度。位宽不是装饰信息，而是决定范围和溢出行为的核心条件。

### 2. 二进制、十进制、十六进制

- 二进制：以 `2` 为基数，只用 `0/1`。
- 十进制：以 `10` 为基数，日常最常用。
- 十六进制：以 `16` 为基数，使用 `0~9` 和 `A~F`。

常用对应关系：

```text
0 = 0000
1 = 0001
2 = 0010
3 = 0011
4 = 0100
5 = 0101
6 = 0110
7 = 0111
8 = 1000
9 = 1001
A = 1010
B = 1011
C = 1100
D = 1101
E = 1110
F = 1111
```

关键规则：

```text
1 个十六进制位 = 4 个 bit
```

工程理解：芯片寄存器、波形窗口、调试日志常用十六进制，因为它比二进制短，又能方便地对应 bit 分组。例如 `0xA5 = 1010_0101`。

### 3. 无符号数

n 位无符号数范围：

```text
0 ~ 2^n - 1
```

例子：

```text
4 位无符号：0 ~ 15
8 位无符号：0 ~ 255
```

工程理解：计数器、地址、长度、索引、ID、状态编号等通常按无符号数理解。

### 4. 补码

n 位补码范围：

```text
-2^(n-1) ~ 2^(n-1)-1
```

例子：

```text
4 位补码：-8 ~ +7
8 位补码：-128 ~ +127
```

快速判断：

- 最高位为 `0`：非负数，正常读。
- 最高位为 `1`：负数，可用“无符号值 - 2^n”。

例子：

```text
1111_1110 作为 8 位无符号 = 254
1111_1110 作为 8 位补码 = 254 - 256 = -2
```

工程理解：补码适合表示有符号整数，而且硬件可以用同一个加法器处理正数和负数的加法。这是补码在计算机和数字电路中非常常见的原因。

### 5. 符号扩展与零扩展

当位宽变大时，需要明确扩展规则。

无符号数通常做零扩展：

```text
1111 作为 4 位无符号 = 15
扩展到 8 位：0000_1111，仍是 15
```

补码有符号数做符号扩展：复制最高位。

```text
1111 作为 4 位补码 = -1
扩展到 8 位：1111_1111，仍是 -1

0111 作为 4 位补码 = +7
扩展到 8 位：0000_0111，仍是 +7
```

工程理解：不同位宽的数据相连时，扩展方式会直接改变数值。8 位 `0xFF` 如果零扩展成 16 位是 `0x00FF = 255`；如果符号扩展成 16 位是 `0xFFFF = -1`。

### 6. 固定位宽加法与溢出

数字电路中的寄存器和加法器通常有固定位宽。n 位结果只能保存低 n 位，超出的进位单独成为 carry out，或者被后级忽略。

例子：

```text
  1111
+ 0001
------
1 0000
```

如果只保存 4 位：

```text
结果 = 0000
carry out = 1
```

按无符号理解：

```text
15 + 1 = 16
4 位无符号范围 0~15，溢出
保存结果回绕为 0
```

按补码理解：

```text
-1 + 1 = 0
4 位补码范围 -8~+7，结果正确，不溢出
```

工程理解：硬件只产生 bit 结果；是否溢出取决于这个字段的位宽和解释方式。计数器回绕、数据截断、累加器溢出都属于这个问题。

### 7. 无符号溢出与补码溢出

无符号溢出：数学结果超出 `0~2^n-1`。

例子：

```text
4 位无符号：1111 + 0001
15 + 1 = 16，超出 0~15
```

补码溢出：数学结果超出 `-2^(n-1) ~ 2^(n-1)-1`。

例子：

```text
4 位补码：0111 + 0001
+7 + +1 = +8，超出 -8~+7
保存 bit 为 1000，按补码解释为 -8
```

工程理解：同一个 bit 结果，在无符号和补码两种解释下，溢出结论可能完全不同。判断前必须先知道信号的设计含义。

### 8. BCD 码

BCD 用 4 bit 表示一个十进制数字。

例子：

```text
0011_1001 = 39
0100_1001 = 49
```

注意：BCD 不是普通二进制数。比如 `0011_1001` 按普通二进制无符号读是 `57`，但按 BCD 读是 `39`。

工程理解：BCD 在普通运算数据通路里不如二进制常见，但在显示、十进制计数、金融金额、人机接口等场景可能出现。

### 9. 工程中的核心判断顺序

遇到一个 bit 串时，按下面顺序判断：

```text
1. 先看位宽：这是几 bit？
2. 再看书写方式：二进制、十六进制还是十进制显示？
3. 再看编码规则：无符号、补码、BCD，还是其他编码？
4. 最后看工程含义：计数器、地址、长度、偏移值、误差值还是状态字段？
```

一句话总结：

```text
bit 串本身没有正负含义；位宽决定范围，编码规则决定解释，工程语境决定该用哪种解释。
```
